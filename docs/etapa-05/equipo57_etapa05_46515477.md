## 1. Aporte realizado
Me encargué de investigar, documentar e implementar el Tema 1 Procedimientos y funciones almacenadas. Hice los scripts SQL para crear un CRUD completo sobre la tabla `CLIENTE` utilizando procedimientos almacenados, y programé tres funciones escalares para automatizar cálculos del negocio (concatenación de nombres, cantidad de compras y monto total gastado). También redacté la justificación teórica y armé los lotes de prueba.

## 2. Decisiones en las que participé
Decidimos hacer los procedimientos almacenados en la tabla `CLIENTE` para encapsular las reglas de altas, bajas y modificaciones, evitando que se manipule la tabla directamente. Además, definimos que las funciones debían ser de tipo escalar para poder llamarlas fácilmente desde un simple `SELECT` a la hora de armar reportes.

## 3. Problemas o dificultades identificadas
Durante la ejecución de los scripts de demostración, tuve dos trabas principales con el motor SQL. Primero, saltaron varios errores de restricción `NOT NULL` (error 515) porque en los primeros intentos de `INSERT` faltaban mandar datos obligatorios de la tabla (Localidad, Teléfono, Calle, Altura). Después, tuve problemas con violaciones de `PRIMARY KEY` (error 2627) porque al ejecutar el lote de prueba varias veces, los números de DNI se duplicaban y chocaban con los que ya estaban guardados.

## 4. Soluciones o propuestas realizadas
Para solucionar los errores de valores nulos, modifiqué el código del procedimiento `sp_InsertarCliente` y los lotes de prueba agregando todos los parámetros que faltaban. Para el problema de las claves duplicadas, la solución fue incluir una sentencia `DELETE` al principio del script de demostración que limpia los DNI de prueba antes de empezar; así el código se puede ejecutar todas las veces que sea necesario sin que se rompa.
