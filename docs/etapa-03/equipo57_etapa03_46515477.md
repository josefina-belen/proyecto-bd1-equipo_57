## 1. Aporte realizado
Yo me encargué de hacer toda la parte de las pruebas de integridad referencial (las Foreign Keys) para el script de validación. Básicamente armé el código SQL para comprobar que los bloqueos anden bien y que los borrados y actualizaciones en cascada afecten correctamente a las demás tablas. También me ocupé de juntar mi código con el de mi compañero y subir el archivo final (`01_pruebas.sql`) a la carpeta correspondiente en nuestro GitHub.

## 2. Decisiones en las que participé
Con mi compañero decidimos dividirnos el script de pruebas en dos para poder terminar a tiempo. De mi lado, tuve que elegir bien qué datos de prueba convenía intentar modificar o borrar para asegurarme de que las restricciones de la base de datos saltaran cuando correspondía.

## 3. Problemas o dificultades identificadas
Cuando estaba probando las actualizaciones y borrados en cascada, me di cuenta de que correr el comando y que no tire error no era suficiente. Necesitábamos alguna forma de demostrar visualmente que los datos relacionados (como los detalles de una venta) de verdad se habían borrado o actualizado por detrás y no quedaban colgados en la base de datos.

## 4. Soluciones o propuestas realizadas
Lo que hice para solucionar eso fue agregarle unas consultas `SELECT` justo después de cada `UPDATE` o `DELETE`. Así, cuando corrés el script, la consola te muestra al instante cómo quedaron las tablas "hijas" y se nota que la propagación en cascada funcionó bien.
